# PPT 디자인 (한국어 학술 발표)

편집 가능한 PPTX를 PptxGenJS로 만든다. 그래프는 다시 그리지 않고 PDF 원본을 잘라 넣는다. 결과물은 "텍스트가 적고, 그림이 크고, 모든 수치에 출처가 붙은" 슬라이드다.

## 1. 디자인 시스템

### 캔버스와 격자
- 16:9 (`LAYOUT_WIDE`, 13.33 × 7.5 in). 좌우 여백 0.5 in, 본문 폭 12.3 in.
- 세로 구역: 상단 앰버 띠(0–0.08) → 섹션 라벨(0.22) → 제목(0.5–1.25) → 본문(1.4–6.9) → 출처 줄(7.05).
- 2단 배치 기본값: 그림 6.3–8.4 in + 텍스트 3.9–5.6 in. 3단 카드: 폭 3.9–4.0 in, 간격 0.2–0.3 in.

### 색 (scripts/deck.js `PALETTE`)
| 이름 | 값 | 용도 |
|---|---|---|
| NAVY | `1F2A44` | 제목, 표 머리글, 표지 배경 |
| AMBER | `C8902E` | 상단 띠, 섹션 라벨, 강조 callout |
| RED | `B23A3A` | 위해·우려·경고, 주의 문구 |
| GREEN | `2E7D5B` | 안전·기준 이내·긍정 결과 |
| PURPLE | `5B4B8A` | 두 번째 범주(예: AGEs vs NAs) |
| STEEL | `5A6E96` | 경로 도식의 중간체 상자 |
| GREY | `5A6170` | 캡션, 하위 bullet, 출처 |
| LIGHT | `F4F1EA` | 패널·callout 배경 |

색은 의미로만 쓴다. 빨강 = 우려, 초록 = 안전. 같은 색을 다른 뜻으로 재사용하지 않는다.

### 글꼴과 크기
- 글꼴: 맑은 고딕(`Malgun Gothic`). 수식만 `Cambria Math`.
- 제목 28 pt 굵게(한 줄, **한글 기준 약 32자 이내**). 표지 제목 32 pt(두 줄까지).
- 본문 bullet 15–18 pt, 하위 bullet은 3 pt 작게 회색. 표 13–14 pt. 캡션 10.5–11 pt. 출처 10 pt.
- 한 슬라이드 bullet은 최상위 3–5개. 문장 대신 "명사구 + 화살표(→, ↑, ↓)".

### 슬라이드 유형 (각각 deck.js 함수)
| 유형 | 함수 | 쓰는 곳 |
|---|---|---|
| 표지 | `titleSlide` | 네이비 배경, 앰버 세로 막대, 원제는 이탤릭 부제 |
| 본문 틀 | `base` + `time` | 모든 내용 슬라이드. 오른쪽 위 발표 시간 |
| 그림 | `img` + `cap` | 비율 유지 자동 맞춤, 대체 텍스트 필수 |
| 요점 | `bullets` | `{t, sub, bold, color}` 객체로 강조 |
| 강조 상자 | `callout` | 핵심 한 문장, 주의 문구 |
| 패널 | `panel` | 비교(좌우 2단)·3단 카드 배경 |
| 표 | `table` | 네이비 머리글, 줄무늬, 셀 단위 강조 |
| 경로 도식 | `box` + `arrow` | 반응 기전, 실험 흐름, 타임라인 |
| 큰 숫자 | `stat` | "97%"처럼 한 숫자로 말하는 결과 |
| 참고문헌 | `references` | 번호 목록 부록 |

## 2. 작업 순서

1. **원문 읽기**: PDF를 끝까지 읽고 수치·그림 번호·쪽을 메모한다. 인용된 선행연구 결과와 이 논문의 결과를 구분해 둔다.
2. **분량 정하기**: 장당 약 1분. 10분 발표 = 본문 10장(+참고문헌 부록), 합계 9:30 목표. 결과 슬라이드가 전체의 40–50%.
3. **그림 자르기** (`scripts/crop_figures.py`):
   ```bash
   python3 crop_figures.py blocks paper.pdf --pages 4-12 --out work/   # 페이지별 내용 블록 y좌표
   # spec.json: {"fig1": [5, 150, 985], "fig4eh": [8, 1038, 1912]}
   python3 crop_figures.py crop paper.pdf spec.json --out work/        # 자르기 + work/sheet.png
   ```
   `sheet.png`를 열어 축 라벨·범례·패널 문자 잘림, 캡션·본문 섞임을 확인하고 y 범위를 고친다.
4. **빌드**: 작업 폴더에서 `npm i pptxgenjs` 후 아래 뼈대로 작성.
   ```js
   const { createDeck } = require("/home/user/Dasom/.claude/skills/ppt-design/scripts/deck.js");
   const d = createDeck({ figDir: "work/", source: "Wang et al. (2025) Food Chem 474:143228", title: "..." });
   d.titleSlide({ kicker: "식품화학특론 · 논문 발표", title: "한국어 제목\n둘째 줄", subtitle: "Original English title",
     authors: "Wang W, ...", citation: "Food Chemistry 474 (2025) 143228 · doi:...", notes: "[0:00–0:20] 대본" });
   const s = d.base("결과 ① 한 줄 메시지형 제목", "결과", "Fig. 1, p.5"); d.time(s, "1:00");
   d.img(s, "fig1.png", 0.4, 1.4, 8.4, 4.6, "그림이 보여 주는 내용"); d.cap(s, "Fig. 1 원본: ...", 0.4, 6.05, 8.4);
   d.bullets(s, ["핵심 1", { t: "보충", sub: true }, { t: "강조", bold: true, color: d.C.RED }], 9.0, 1.5, 3.9, 5.3, 15);
   s.addNotes("[2:30–3:30] 그대로 읽을 수 있는 대본");
   d.save("/home/user/Dasom/발표.pptx");
   ```
   `require` 위치에서 pptxgenjs를 못 찾으면 `NODE_PATH=$(pwd)/node_modules node build.js`로 실행한다.
5. **렌더링 점검** (`scripts/render_check.sh deck.pptx out/`): `out/review.png`를 열어 확인하고, 문제가 있으면 고친 뒤 다시 돌린다.

## 3. 품질 규칙

- **제목은 메시지형**: "결과 ④ AGEs" 대신 "결과 ④ AGEs: 소금은 CEL↓, 지방은 CML↑". 단, 한 줄을 넘기면 줄인다(가장 흔한 레이아웃 오류).
- **모든 결과 슬라이드에 출처**: `base()`의 세 번째 인수로 "Fig. 4, 3.6절" 같은 원문 위치를 단다. 그림 아래에는 `cap()`으로 "Fig. N 원본: 무엇을 보여 주는지".
- **그림은 원본 그대로**: 생성형 이미지로 데이터 그래프를 다시 그리지 않는다. 개념도(반응 경로, 실험 흐름)만 `box`/`arrow`로 직접 그리고, 직접 그린 그림이면 캡션에 "(발표자 작성)"을 쓴다.
- **선행연구 구분**: 인용 연구의 결과는 저자·연도를 붙이고, 이 논문의 결과처럼 보이면 `callout(..., RED)`로 분명히 적는다.
- **결론 슬라이드**: "저자 결론"과 "생각해 볼 점(발표자 의견)"을 좌우로 나누고, 맨 아래 Take-home 한 줄을 `callout(..., AMBER)`로 둔다.
- **노트 = 대본**: 각 슬라이드 노트를 `[시작–끝]`으로 시작해 구어체로 쓴다. 대본 시간 합이 목표 시간과 맞는지 확인한다.
- **접근성**: `img()`는 대체 텍스트가 없으면 오류를 낸다. 색만으로 의미를 전달하지 말고 "↑/↓", "초과/이내" 같은 글자를 함께 쓴다.
- **표지 빈칸**: 발표자 이름·학번·날짜는 지어내지 말고 `[이름]` 자리표시로 둔다.

## 4. 렌더링 점검 체크리스트

- [ ] 모든 제목이 한 줄인가
- [ ] 텍스트가 상자·패널 밖으로 넘치지 않는가 (LibreOffice는 글꼴이 바뀌어 약간 넓게 나오니 10% 여유)
- [ ] 화살표 위 작은 라벨이 상자와 겹치지 않는가
- [ ] 그림의 축 라벨·범례가 잘리지 않았는가
- [ ] 출처 줄(7.05 in)과 본문이 겹치지 않는가
- [ ] 슬라이드 수와 시간 표시 합계가 맞는가

## 5. 저작권과 저장

- 논문 라이선스를 확인한다. **CC BY 오픈액세스**면 출처를 밝히고 그림을 써도 된다.
- **"All rights reserved"** 논문의 원본 그림이 든 PPTX는 수업 발표용으로만 쓰고, **공개 저장소에 커밋하지 않는다**(Dasom 저장소는 public). 이런 파일은 세션 작업 폴더(scratchpad)에 두고 사용자에게 파일로 전달한다.
- 대본·정리 문서(.md)처럼 그림이 없는 결과물은 커밋해도 된다.

## 6. 함께 주면 좋은 것

발표 대본·정리 문서(.md)를 같이 만든다: 논문 요약표(원문 위치 포함), 발표할 때 주의할 점, 슬라이드별 시간표와 대본(노트에서 자동 추출), 예상 질문과 답변 3–4개.
